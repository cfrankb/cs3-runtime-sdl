# Test plan — coverage round 2 (`src/` non-SDL blocks)

Tracker: [test-coverage-todo.md](test-coverage-todo.md) rounds T4–T7.
Baseline: `src-coverage.md` 2026-11-16 → **42.2% of 11946 gcov lines**;
`src-checklist.md` → 71/121 verified. This plan covers the ~2300 executable
lines that are reachable without SDL (verified by `grep -c SDL_`, not by
assumption), plus the one suite where SDL is faked by the dummy driver.

## Why these files

`grep -c SDL_` is **0** for `menu.cpp`, `menuitem.cpp`, `menumanager.cpp`,
`gameui.cpp`, `engine.cpp`, `gamemixin.cpp`, `animator.cpp`,
`shared/helper.cpp`, `shared/Frame.cpp`, `shared/FrameSet.cpp`,
`shared/PngMagic.cpp`. They were parked in the old "Tier 4 — UI bound to the
engine loop" bucket on an assumption. They are plain state machines and a
software rasteriser: `CGameMixin::draw*` all take a `CFrame &` and write
pixels through `CFrame`, and `CGameMixin` keeps the glyph atlas
(`m_fontData`) and every tileset (`m_tiles`, `m_users`, `m_animz`,
`m_sheet0/1`, `m_uisheet`, `m_layerTiles`) as protected members a test
subclass can fill in memory.

## Ground rules

- Style: existing harness. One `bool test_xxx()` per area, `LOGE` on failure,
  registered in `tests/tmain.cpp` and picked up by `python bin/refresh.py`
  into the autogenerated `tests/CMakeLists.txt` `TEST_SOURCES` (never hand-edit
  the generated files).
- Assertions are **invariants**, not byte goldens: pixel counts, changed-pixel
  counts, bounding boxes, frame identity/pointer, size + header fields,
  round-trip equality, error-string non-empty. Existing goldens in
  `tests/in/refs/` stay as they are.
- Never hardcode tile ids or asset contents — table-scan and assert the
  attribute/type, the `t_game_ai.cpp` rule.
- Determinism: reset `g_random` (`t_randomz.cpp` pattern) at the start of each
  scenario that touches AI or flashing.
- Private asset tree: anything reading `data/` (a symlink to
  `cs3-data-private`, absent in CI) must use the skip-not-fail guard from
  `t_bossdata.cpp`. Everything below Tiers A–E is written so it needs **no**
  `data/`; prefer synthetic `CFrame`/`CFrameSet` objects.
- No production refactors for testability. Seams are limited to the four
  listed in "Seams" and must be justified one at a time.
- Per phase: `cmake -B build && cmake --build build && ctest --test-dir build`
  green, then `python3 itools/gen_coverage.py` + `python3 itools/gen_compliance.py`,
  flip the checklist boxes for the files that phase turned green. One commit
  per phase, `tests: <area> suites (...)`.

`CMenu`/`CMenuItem` construction: `CMenu(menuid, scaleX, scaleY, padding)`,

| `menu_disabled` | `disable()` items are skipped by `up`/`down`; all-disabled menu is a no-op, not a hang |
| `item_range` | `left`/`right` respect `m_rangeMin/Max`, step by `m_factor`, start from `m_start`; write through the bound `int*`; `left` at min returns false and leaves value |
| `item_options` | options vector: `right` wraps to 0, `option(i)` bounds, `type()`/`role()`/`userData()` accessors round-trip |

| `menu_roles` | `containsRole`, `getItemByRole` hit/miss, `removeRole`, `moveItem(role, pos)` ordering |

Expected: ~246 lines → ≥85% (≈+200).

Result 2026-11-16: menu.cpp 98.1%, menuitem.cpp 97.8%, menumanager.cpp

### C2 `tests/t_frame.cpp` ✅ done 2026-11-16 — `shared/Frame.cpp` (514 @ 29.0%)

All on synthetic 4x4/8x8 frames; assert exact pixel grids where cheap,
otherwise counts.

- transforms: `flipH`, `flipV`, `rotate`, `shrink`, `enlarge` (dimension +
  sampled pixel identity), `shiftUP/DOWN/LEFT/RIGHT` × {wrap, clip} —
  wrapped row reappears on the opposite edge, non-wrapped leaves background.
- fills: `fill`, `clear`, `isEmpty`, `inverse`, `copy`, `shadow`, `fade`
  (monotone direction, not exact factor), `abgr2argb`/`argb2arbg` swap.
- geometry: `resize`, `clip` (exact subgrid + out-of-bounds behaviour),
  `drawAt` with and without transparency, `draw(vector<Dot>, penSize, mode)`
  + `save` (the pair the paint path uses), `floodFill`, `floodFillAlpha`
  (bounded region only; diagonal-not-filled property of the implementation).
- pixels/meta: `isValid`, `setTransparency`/`hasTransparency`/
  `setTopPixelAsTranparency`, `toNet` pure calc, `getChunkType`,
  `split`, `explode` (frame counts + sizes).
- IO: `write`/`read` through `IFile` round-trip (reuse `t_ifile.cpp`
  `IFile` construction), `toBmp` (buffer allocated, BMP header magic/size
  fields), `toPng` with the existing `obl5` byte stream from
  `tests/in/refs` (assert PNG signature + non-empty, no golden).

Expected: → ≥75% (+235).

Result 2026-11-16: Frame.cpp 85.8%, DotArray.cpp lifted to 94.9% via the
draw/save path. Findings pinned by tests: `CFrame` has two `operator=`
overloads (`CFrame src` by-value + `const CFrame&`) that are ambiguous for
lvalue assignment — copies must be copy-constructed; `clip` only treats
`-1` as "to edge" (other negatives or over-wide extents throw
`std::out_of_range`); `fill` stores raw values and `isEmpty` keys on alpha
only; `abgr2argb` drops R/B bytes when alpha is 0. Skipped: `toPng` with
the obl5 side-stream (kept for the PngMagic/obl5 phase).

## Phase E — `tests/t_gamemixin.cpp` extension (1454 @ 15.7%, biggest block)

The file has **no** SDL calls; the dark 1225 lines are software drawing plus
input/game-flow rules. Extend the existing `TestRuntime : CRuntime`
subclass — all members needed are already `protected` (`m_tiles`, `m_users`,
`m_animz`, `m_sheet0/1`, `m_uisheet`, `m_layerTiles`, `m_fontData`,
`m_animator`, `m_game`), so expose them with `using`/accessors in the
subclass. **Graphics fixture** (one helper, built once per process): synthetic
tileset of `N` solid-coloured `CFrame`s assigned to `m_tiles`/`m_layerTiles`,
a users frameset with `PLAYER_TOTAL_FRAMES * users` frames for
`TILES_ANNIE2`, a `m_fontData` atlas of solid glyphs sized to
`(0xFF - ' ' + CHARS_CUSTOM_BASE + 1) * fontOffset` so every codepoint
renders without reading past the vector. Assert invariants only:
non-black pixel count in a clip rect > 0, changed-pixel count between two
states, and that a known tile's colour appears at the mapped coordinates.

Order, cheapest first (each a separate `bool` case, each green before the
next):

1. `draw_tile` — `drawTile(bitmap, x, y, tile, alpha, colorMask, colorMap)`
   both overloads + `drawTileFaz`: colour at target rect, clipping at
   negative x/y and at the far edge, alpha vs opaque, each `ColorMask`
   branch, `colorMap` substitution actually changes the pixel.
2. `tile2frame` — `tile2Frame` returns `nullptr` for `TILES_STOP`/
   `TILES_BLANK`/`m_animator->isSpecialCase()` tiles, the `TILES_ANNIE2`
   branches (dead / no-goals-closure / idle-aim-down / normal aim) each pick
   the expected `m_users` index, ordinary tile picks its `m_tiles` index.
3. `viewport_static` / `viewport_dynamic` — `drawViewPortStatic`/
   `Dynamic(CFrame &)` against `CGame::getGame().getMap().resize(...)` + the
   `g_layerdata` entries from `t_game.cpp`: non-empty output, camera offset
   changes which tile colour lands where, `changeZoom` scale path.
4. `draw_bosses` — `drawBossses(bitmap, mx, my, sx, sy)` with the
   skip-guarded production bossdata (`t_boss.cpp`) + synthetic user frames;
   hitbox/`drawFont6x6` name-plate branch reached once, off-screen boss draws
   nothing.
5. `screens` — `drawScreen(CFrame &)`, `drawScores`, `drawLevelIntro`,
   `drawMenu`: recorded-pixel invariants (region non-empty, score rows
   present for N hiscores, intro shows level name/title branch).
6. `input_rules` — `handleFunctionKeys_Game(k)` per key (pause/resume,
   restart-confirm state, hi-score erase state), `handleInputString(inputDest,
   limit)` accepted/rejected chars + `limit` truncation,
   `handleFunctionKeys_General(k)`, `setSkill`/`enableHiScore`/
   `setWidth`/`setHeight` state effects.
7. `game_flow` (last, riskiest) — `manageGamePlay()` and `mainLoop()` driven
   for N fixed ticks on a tiny map: assert state transitions only
   (`isPaused`, timer, tick counter, closure flag). Skip any branch that
   reaches audio/menu I/O; do not add seams to escape it.

Expected: ≥55% of the file (≈+640 of 1225 dark lines). If 3–5 stall on asset
loading, stop and record it; do not add product seams to force them.

## Known risks

1. Phase E 3–5 may need real animationz/sheet data; mitigate with synthetic
   framesets, stop at the first sign of an asset rabbit hole.
2. `Engine::getEventText` vs `CGameMixin::getEventText` duplication: if the
   parity assertion fails, that is a finding — report it, do not "fix" the
   test to pass.
3. `CFrame::floodFill`/`explode`/`split` may have edge-case bugs (this
   harness has found 8 so far). File them as findings in the commit message
   the way `maparch`/`addKey` were, and keep the test asserting correct
   behaviour only after the product fix.
4. gcov function attribution is polluted by inlined `std::` templates — the
   Phase G gen_coverage change must filter them or the report is useless.
5. `tests/out` is shared by all suites; namespace new scratch files
   (`frame_`, `helper_`, `gm_` prefixes) to keep `compareFiles` checks isolated.
