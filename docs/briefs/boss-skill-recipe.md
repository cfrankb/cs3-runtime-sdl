# Brief: Adding a new boss skill

Audience: AI agents + users. Recipe for wiring one new castable boss attack
end to end. Authoritative spec: `docs/spec/gamespec/boss-skills.md`
(+ `docs/spec/gamespec/extended-fx.md` for the fx layer itself).

A skill is one row in the hand-authored registry `g_skillDefs`
(`src/bossdata.cpp`); a boss then declares it with `skill NAME rate=N` ini
lines. Three kinds:

| kind | when to pick |
|------|--------------|
| `SKILL_BULLET` | boss projectile attack; slot is self-contained (`tile=` mandatory + optional `algo=`/`sound=`/`ttl=`) |
| `SKILL_SPECIAL1` | rate-gating boss contact damage only |
| `SKILL_FX` | new tile-targeted animated attack (this recipe) |

The registry is static loaded data, **not** serialized state: no
`ENGINE_VERSION` bump needed (AGENTS.md rule applies to `CActor`/`CMap`/
`CLayer`/savegame changes only).

## 0. Reuse or author the fx art

Lazy path: reuse one of the 9 fx already in `g_fxData`
(`src/gamesfx.cpp`) — its id (`enum Fx`, `src/sfx_public.h`) and frame run
(`enum FxLayer`, `src/sfx_private.h`: `FX_<NAME>_BASEID` / `_FRAMES`).
The existing rows cover lightning, fire column, mushroom, ice spikes, smoke,
explosion, bomb fuse/explosion, poison aura.

Only if new art is required: extend the fx sheet pipeline — both enums above
are "generated by sheet, do not edit"; the frame sequences come from
`cs3-data-private/pixels/sfx.idx` and the `sfx.png` obLT chunk. See
`docs/spec/gamespec/extended-fx.md` for the sheet contract, then add a
`g_fxData` row (`id`, `speed` ticks/frame, `FX_ONESHOT`, `w/h`, `align`
(`FX_ALIGN_BOTTOM` for tall skyfalls), `front`/`back` layer base+count).

## 1. Registry row (`src/bossdata.cpp`, `g_skillDefs`)

Append a designated-initializer row (spell trailing members out,
`-Wmissing-field-initializers`):

```cpp
{.name = "ICE_SPIKES",          // unique ini token
 .kind = SKILL_FX,
 .effectId = FX_ICE_SPIKES,     // damaging fx (index into g_fxData)
 .telegraphFx = -1,             // optional marker fx spawned at cast time
 .telegraphTtl = 18,            // lead time in ticks (24 Hz): 18 = 3/4 s
 .damage = 12,                  // hp per collision registration
 .baseFrame = FX_ICE_SPIKES_BASEID, // first fx-sheet frame of the hitbox run
 .hitboxFile = "ICE_SPIKES.json",   // under <assets>/fx/ (see §2)
 .frames = {},                  // filled by loadFxSkills
 .firstHitFrame = -1,
 .lastHitFrame = -1},
```

Copy `LIGHTNING_STRIKE` / `METEOR` right above; they are the working model.

## 2. Hitboxes (`<assets>/fx/<NAME>.json`)

`loadFxSkills(AssetMan::getPrefix() + "fx")` (called from
`src/engine_hw.cpp` beside `loadBossData`) fills `frames` from
`<assets>/fx/<hitboxFile>`. Same §0b grid schema as the boss per-aim JSONs
(`readHitboxJson` core), with fx twists: boxes are keyed by plain fx-sheet
frameID `baseFrame + rawId` (no `SHEET_SPACER`), box `x/y` become px offsets
from the frame center anchor, no half-tile quantization. Damaging boxes are
`type: 2` (SPECIAL1 vocabulary, separate consumer).

Example for the 6-frame 32x48 `FX_ICE_SPIKES` run, one box on the last
frame only (col `x/width` picks the frame; `rawId = row*cols + col`):

```json
{
    "frame": { "cols": 6, "height": 48, "width": 32 },
    "hitboxes": [
        { "x": 164, "y": 40, "w": 24, "h": 8, "type": 2 }
    ]
}
```

Rules that matter (`tickFx` collision, spec §4):

- **Box authoring is the damage window.** Frames absent from the JSON never
  damage → the lead-in frames before the first box are free telegraph time.
- Max `MAX_HITBOX_PER_FRAME` (4) boxes per frame; extras `LOGW` + dropped.
- A missing/w unreadable JSON is a `LOGW`, boxes skipped: the skill animates
  but never damages.
- Shortcut instead of a JSON: set `hitboxFile = nullptr` +
  `default_box = true` — one synthesized bottom rect (`w x 8` px) on the
  fx's last frame. Skill with neither source never damages.

## 3. Hint / lead time

Set on the registry row; consumed by `CGame::manageBosses` (Chase branch,
`src/game_ai.cpp`) and `scheduleFx`/`tickFx` (`src/game.cpp`):

- `telegraphTtl > 0`: cast calls `scheduleFx(effectId, player.x(), player.y(),
  telegraphTtl)` — the strike lands on the tile the player stands on
  **at cast time**, `telegraphTtl` ticks later. Both renderers tint the
  target tile 25% red meanwhile (placeholder for the deferred marker art,
  `docs/plans/telegraph-art-task.md`; `fxDraw_t::telegraph` flag).
- `telegraphTtl == 0`: no warning, immediate `spawnFx` (legacy).
- `telegraphFx >= 0`: additionally spawns that marker fx on the same tile at
  cast time (use an existing fx like `FX_SMOKE_BOMB` as a stand-in marker).
- `playSound(bd->attack_sound)` fires with the cast — give the boss a real
  `attack_sound` in the ini, not just `SOUND_NONE`.
- Pending strikes are transient CGame state: save/load drops them, the boss
  just recasts. Do not serialize them.

Effective dodge window ≈ `telegraphTtl` ticks + hitbox lead-in frames.

## 4. Declare it in `bosses.ini` (`<assets>/bosses/bosses.ini`)

Repeated `skill` lines, max 4 per boss, file order = slot order.
`rate` is the rng gate: each tick in Chase, `rng.range(0, rate) == 0` casts
(lower = more often; `rate 0` = declared, never fires — except `BULLET`,
where rate 0 is rejected at load). Unknown token: `LOGE` + skipped. 5th
line: `LOGW` + ignored.

```ini
[Mr. Demon]

type            0xb0
...
attack_sound    SOUND_DINOSAUR3
...
skill           BULLET rate=15 tile=TILES_FIREBALL algo=Path::NONE sound=SOUND_SHOOT3 ttl=NoTTL
skill           ICE_SPIKES rate=30
```

Notes:

- `BULLET` slots are self-contained: `tile=` is mandatory and non-blank and
  `rate > 0`, else the line is skipped with `LOGE`. `algo=`, `sound=`,
  `ttl=` are optional payload keys. The old standalone `bullet` ini keyword
  is retired (2026-11-25) — migrate
  `bullet T rate=N algo=A sound=S ttl=T` ->
  `skill BULLET rate=N tile=T algo=A sound=S ttl=T`; a blank-tile
  `bullet TILES_BLANK rate=N` line is dropped entirely (the
  `BOSS_FLAG_PROXIMITY_ATTACK` lunge is gated by the `SPECIAL1` slot rate,
  never by bullet data).
- Bosses with no `skill` lines have no cast attacks.

## 5. Verify

```sh
cmake -B build && cmake --build build
ctest --test-dir build -R "bossdata|fx|game_ai"
```

Mechanism coverage exists (`test_bossdata_skill_ini`,
`test_bossdata_fxskills`, `test_fx_skill_hit`, `testBossSkillCast`); a pure
data addition (new row + JSON + ini lines) needs no new test. Add/extend one
only if you change loader or combat logic. Then run the game and watch: hint
tile appears, sound fires, fx lands, damage only during the authored frames.
