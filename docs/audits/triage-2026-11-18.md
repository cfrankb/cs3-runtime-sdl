## 2. P1 — remaining hardening, live paths

1. **FileWrap.cpp L71-85** — no negative-size validation on `read`/`write`;
   `fread(buf, neg, 1)` becomes a huge `size_t`. FileMem got its guards in
   BUG-C2; the disk backend is the sibling that never did. Two one-line
   checks (`size < 0` → `IFILE_NOT_OK`), plus `getSize()` ignoring the
   `ftell` -1 (L124-127). Do it despite the FROZEN header — these are
   implementation guards, not contract changes.
2. **bossdata.cpp Medium x7** — loader trust boundary for `bosses.ini`/JSON
   mods: unbounded parser recursion depth, bare `atoi` everywhere, `aims`
   not clamped >= 1 (boss.cpp only clamps at use), `@ref` error handling,
   duplicate keys/sections silently accepted. Criticals are fixed; this is
   the remaining validation backlog at a mod-data trust boundary.
3. **boss.cpp L304-312** — `currentFrame()` still unclamped against actual
   frame-set size. The render symptom is guarded (BUG-C8 added range+null
   check in `drawBossses`), so this is now defense-in-depth: clamp in
   `currentFrame()` and/or loader cross-check of `base/lenght/aims` totals.
4. **Frame.cpp Medium x9** — public shared API with test-only callers today
   but external LGCK-builder exposure: unenforced `m_rgb.size()==w*h`
   invariant (`setRGB`/`getRGB`), `clip()` throw-vs-null incoherent
   contract, negative-dot throw in `draw()/drawAt()/save()`, `shadow(0)`
   SIGFPE, recursive `floodFill` stack overflow, `shiftLEFT/RIGHT` guard
   copy-paste (`m_height` should be `m_width`), `write()` header-before-size
   check. None fires in the runtime today; cheapest wins are the `shadow`
   guard and the `shiftLEFT/RIGHT` guard (real bug, live caller
   `gamemixin.cpp:505`).
