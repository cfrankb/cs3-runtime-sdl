# Audit: src/shared/logger.h
Date: 2026-11-17

## Summary
A tiny, working logging facade whose only real problem is that it is a near-byte-identical copy of `src/logger.h` — a second live copy of the same class definition that has already drifted (its USE_QFILE branch omits `#include <QDebug>` and would not compile if that dead flag were ever enabled). The LOGF macro is a latent `exit(1)`-on-the-wrong-branch hazard with zero callers, and the entire Qt/USE_QFILE block including a `#define printf qDebug` reserved-identifier macro is dead everywhere in the repo. Counts: 0 Critical, 3 High, 3 Medium, 1 Low.

## Findings

### High
**FIXED 2026-11-17 (BUG-H16):** copies now byte-identical with keep-in-sync note; consolidation stays open. **L31-73: [shrink] This file duplicates `src/logger.h` — diff shows the only differences are a missing `#include <QDebug>` in the USE_QFILE branch (L52-53, so that branch cannot compile here) and a missing trailing newline; both headers are live (all `src/*.cpp` resolve `#include "logger.h"` to `src/logger.h`, all `src/shared/*.cpp` resolve the same quoted include to *this* file), so the two class definitions of `Logger` can diverge into an ODR violation at any time. Fix: delete this file and make `src/shared` consumers include the single canonical `src/logger.h` (shared sources are already re-exported into the main target by `src/shared/CMakeLists.txt`).
**FIXED 2026-11-17 (BUG-H16):** Qt block kept as maintainer compatibility layer; both copies now carry the identical block (`QtLogging` + `QDebug` includes). **L52-58: [dead][ub] The whole `USE_QFILE`/Qt block never compiles — no CMakeLists or build config anywhere defines `USE_QFILE` (same finding already recorded in `docs/audits/helper.cpp.audit.md` L17 and `gamemixin.audit.md` L39) — and it contains `#define printf qDebug` (L54), a macro over the reserved standard-library name `printf` which is UB and would silently rewrite every `printf` call site in any TU that includes this header if the flag were ever turned on (wrong return type, wrong semantics). Fix: delete L52-58 (and the mirrored block in `src/logger.h`); nothing uses it. *(Resolution 2026-11-17: not deleted — maintainer requires the Qt compatibility layer; drift fixed by restoring identical blocks instead. The `printf`/`QDebug` hazard remains if the flag is ever enabled.)*
**TRIAGED 2026-11-17 (BUG-H16):** `LOGF` kept on maintainer instruction; a DO-NOT-DELETE comment now guards it (and the Qt block) in both copies, plus the standalone-statement caveat at the top of the header. The unbraced-`if` hazard below remains known, not fixed. **L69-71: [dead][bug] `LOGF` expands unbraced to `Logger::log(...); exit(1)`, so `if (cond) LOGF("...");` logs conditionally but exits *unconditionally* (the `if` guards only the log call, `exit(1)` is a separate statement); the doc-comment example at L20 invites exactly this usage. It also calls `exit(1)` from the caller's context, skipping stack unwinding and SDL teardown. Verified zero call sites in src/, tests/, docs-spec code. Fix: delete the macro (YAGNI — nothing calls it); if a fatal logger is ever wanted, wrap in `do { ... } while (0)`, mark the function `[[noreturn]]`, and keep the exit in exactly one place.

### Medium
- L43: [bug] `static void log(Level, const char *tag, const char *format, ...)` lacks `__attribute__((format(printf, 3, 4)))`, so the compiler performs *no* format-string checking on any of the ~1,100 LOGx call sites even though the build uses `-Wall -Wextra` (top-level `CMakeLists.txt:173`) — `-Wformat` cannot check a variadic without the attribute, and existing calls already mix `%lu`/`%zu`/`%lld` (`maparch.cpp:533`, `assetman.cpp:85`, `runtime.cpp:240`). Fix: add `#if defined(__GNUC__) __attribute__((format(printf, 3, 4))) #endif` to the declaration (expect a first-time warning sweep across the repo).
- L60-68: [bug] LOGI/LOGW/LOGE expand to a bare `if (cond) Logger::log(...);` with no `do { ... } while (0)` wrapper, so `if (a) LOGE(...); else ...` binds the `else` to the macro's internal `if` (wrong behavior or hard compile error) and the macro swallows context in other brace-less positions. Verified no current breakage: multiline scan of src/ and tests/ found no `LOGx(...);\s*else` pattern and every observed `else` chain wraps the macro call in braces. Fix: `do { if (...) Logger::log(...); } while (0)`.
- L41 + L44/L61: [ub][shrink] `m_minLevel` is read without synchronization by every macro (`Logger::level()`) while `setLevel` writes it non-atomically → data race if the level is ever changed after threads start logging. Currently latent: `Logger::setLevel` and `Logger::setOutputFile` have zero callers in src/ (only `tests/t_logger.cpp`), the `--verbose` flag (`parseargs.cpp:175`) logs but never sets the level, so in the shipped app the three level-filter checks in the macros are always true and the file-sink API is configured-but-unused flexibility. Fix: make `m_minLevel` `std::atomic<Level>` (one word change) and either wire CLI verbosity/`-q` to `setLevel` or delete both setters.

### Low
- L46-49: [ub][error-handling] The statics `m_minLevel`/`m_output`/`m_mutex` (defined `src/logger.cpp:28-30`) have static storage duration: any `log()` call from a static destructor, atexit handler, or a second thread during process teardown uses a destroyed `std::mutex` (UB); the FATAL path makes this concrete because `src/logger.cpp:68-69` calls `exit(1)` *while holding* `m_mutex` (acquired at `logger.cpp:43`), so a concurrent log from another thread deadlocks against a locked mutex mid-exit — and the `exit(1)` in this macro (L71) plus the one in `log()` is a redundant double-exit. Fix: keep the exit in one place (the macro or the function, not both), outside the lock, and note in the header that logging during static destruction is unsupported. (needs verification under a thread-sanitizer build that a FATAL-while-logging path exists; LOGF has no callers today.)

## Notes
- Usage counts (ripgrep over `src/`, `tests/`, excluding the two logger headers' own definitions and `docs/spec` reference copies): LOGE ≈ 908, LOGI ≈ 178, LOGW ≈ 49, LOGF = 0. All four levels are named, but only three are exercised because `setLevel` is never called at runtime (default `L_INFO` passes everything).
- There is no `src/shared/logger.cpp`; all `Logger` symbols are defined exactly once in `src/logger.cpp` (compiled via `src/CMakeLists.txt:25`). `src/shared/CMakeLists.txt` compiles no logger TU — `shared_lib` only links because its sources are re-exported into the main executable target; anyone linking `shared_lib` standalone gets undefined `Logger::log`.
- Cross-file facts: the header's `__FILE_NAME__` tag is native on the build compiler (GCC 16.2.1); a fallback definition for GCC < 12 lives at top-level `CMakeLists.txt:11-18`. `tests/t_logger.cpp` includes `../src/logger.h` (the `src/` copy, not this one), exercises `setLevel`/`setOutputFile`/newline handling, and deliberately never calls LOGF because it `exit(1)`s.
- `setOutputFile` failure handling lives in `src/logger.cpp:38`: a failed `fopen` silently resets routing to stdout and the previous sink is closed first; the `m_output != stdout && m_output != stderr` guard (logger.cpp:34) is dead since nothing ever assigns those to `m_output`.
- Android branch `src/logger.cpp:52-55` uses `ANDROID_LOG_*`/`__android_log_vprint` with no `<android/log.h>` include anywhere — only reachable when `__ANDROID__` is defined but `SDL_MAJOR_VERSION` is not; (needs verification against an actual Android build, which was not performed here).
- Suggested runtime verification: (1) add the `format(printf)` attribute and rebuild with `-Wall` to size the existing format-mismatch backlog; (2) run the test suite under TSan after making `m_minLevel` atomic; (3) confirm no CI job ever passes `-DUSE_QFILE` before deleting the Qt blocks in both headers.
