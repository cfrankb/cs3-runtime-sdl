# Audit: src/game_ai.cpp
Date: 2026-11-17

## Summary
The file is structurally sound — the deferred-delete (`deletedMonsters` as `std::set<int, std::greater<int>>` + descending erase) and deferred-spawn (`newMonsters`) patterns in `manageMonsters` are correctly designed, and `queueRespawn(int)` bounds-checks properly. However, several kill paths (bullet splash vs. icecube/vamplant, `handleVamPlant`, `pushChain`) fail to consult `deletedMonsters`, which allows double-kills → duplicate respawn entries and map tiles overwritten (PU restored by blast then clobbered to `TILES_BLANK`). `speeds[def.speed]` is an unchecked data-driven stack index. Counts: 0 Critical, 3 High, 7 Medium, 12 Low.

## Findings

### High
**FIXED 2026-11-17 (BUG-H11):** deleted-count guard added to both branches. **L890-L897, L912-L919: [bug] `handleBullet` icecube/vamplant splash branches call `findMonsterAt` + `queueRespawn(i)` + `deletedMonsters.insert(i)` without the `!deletedMonsters.count(id)` guard that `blastRadius` correctly applies at L754. If the target was already killed earlier this tick (e.g. barrel blast), `queueRespawn` runs a second time (duplicate spawn entries → double respawns) and `m_map.set(pos, TILES_BLANK)` clobbers the PU tile that the blast already restored, permanently deleting the underlying tile. Fix: skip when `deletedMonsters.count(id)`, matching L754.
**TRIAGED 2026-11-17:** latent only; call-site warning comment added. **L387 + L540 (via `handleMonsterV3`): [ub] `spawnBullet` does `m_monsters.emplace_back` (src/game.cpp:1836-1846 confirms vector storage), which can reallocate and dangle the `CActor &actor` reference bound at L387 and passed into `handleMonsterV3`. Today nothing touches `actor` after the `spawnBullet` call (function returns immediately), so it is latent — one added statement after L540 turns this into use-after-free. Note the irony: L453 comments "moved here to avoid reallocation while using a reference", yet this call path still reallocates mid-reference. Fix: reserve headroom for `m_monsters`, or re-fetch by index after spawning.
**FIXED 2026-11-17 (BUG-H11):** deleted set passed in and consulted. **L630-L635: [bug] `handleVamPlant` converts a monster found via `findMonsterAt` with no `deletedMonsters` guard: a monster already marked for deletion this tick is converted to `TYPE_VAMPLANT` and `m_map.set(p, TILES_VAMPLANT)` runs, but the actor is erased at end of `manageMonsters` → orphaned VAMPLANT tile with no actor (and the blast-restored PU tile is overwritten). Fix: same deleted-check; pass the set (or an `isDeleted` predicate) into `handleVamPlant`.

### Medium
**FIXED 2026-11-18: capture is now `&boss`.**
- L214: [bug/perf] Lambda captures `boss` **by value** — `CBoss &boss` is a reference parameter, so `[boss, this, &playerDamage]` deep-copies the entire `CBoss` object (`m_bosses` is `std::vector<CBoss>`, game.h:225) per hitbox callback creation. Only `boss.damage()` (const) is used, so behavior is accidentally correct. Fix: `[&boss, this, &playerDamage]`.
**FIXED 2026-11-18: `boss` capture dropped.**
- L795: [dead] `[boss, &bp, &bossDamage]` — `boss` is never used in the lambda body (only `bp` and `bossDamage`), yet a full `CBoss` copy is made per (boss × blast position). Drop the capture.
**CLOSED 2026-11-18 — DESIGN RULING (maintainer): blast damage applies to
bosses regardless of state, Hidden included; the loop's lack of a state
guard is intentional and now commented in `game_ai.cpp`. Corpse
double-counting was verified impossible (`subtainDamage` fires `justDied`
only on the death transition; repeat Death-state hits are no-ops). Pinned
by `t_game_ai` scenario "hidden boss blast".**
- L786-L803: [bug] (needs verification) `blastRadius` boss damage loop has no `boss.state()` check (unlike `manageBosses` L282/L292, which skip Hidden/Death). A dead boss can absorb splash and re-enter `subtainDamage`; if `subtainDamage` re-triggers death effects (score/state), killing near a corpse double-counts. Verify `CBoss::subtainDamage` and add a state guard.
**VERIFIED 2026-11-18 — NOT A BUG: `CGame::addHealth` gates god mode
internally (`!S_GOD_MODE_TIMER && hurtStage == HurtNone`, game.cpp:934-943),
which is exactly what `isGodMode()` tests. Splash via `addHealth` respects
god mode and also inherits invincibility frames; the explicit `!isGodMode()`
call-site checks guard their extra side effects, not the health math.**
- L743-L747: [bug] (needs verification) Blast splash damages the player via `addHealth(radiusDamage)` with no `isGodMode()` check, while `handleCrusher` (L650), `handleIceCube` (L682) and `handleBullet` (L899) all gate damage on god mode. If `addHealth` does not gate god mode internally, god mode wrongly dies to barrels. Make consistent.
- L400: [ub] `speeds[def.speed]` — `TileDef::speed` is `uint16_t` from autogenerated data (tilesdefs.h:31) indexing a 9-element stack array with no clamp. Current `src/tilesdata.cpp` values are 0-6, but any tile def with speed ≥ 9 is an out-of-bounds read. Fix: `def.speed < speedCount ? speeds[def.speed] : true` with a `LOGW` (or validate at data load).
- L212: [bug] (needs verification) Player contact test hardcodes `m_map.at(...) == TILES_ANNIE2` while every other player-detection site uses `def.type == TYPE_PLAYER` (L615). Any other player tile id (boat/variant frames) is invisible to boss hitbox contact damage. Use the tile type.
- L144-L160: [bug] (needs verification) `handleBossPath` runs the fallback chase movement unconditionally after `boss.followPath()` may already have moved the boss this tick — potential double-move per tick when a path algo is active. Gate the fallback on the path result.

## Notes
- Runtime verification needed for: (1) `CBoss::subtainDamage` re-death behavior against dead bosses (Medium L786 finding) and per-hitbox-tile repeat damage when two hitboxes overlap one icecube tile (L237-L242 applies `ICE_CUBE_DAMAGE` per `HitResult` even when the monster lookup already returned INVALID); (2) whether `testHitbox1` reports the same map position once per overlapping hitbox (drives both the double-damage question above and the L214 repeat player damage — player damage is protected by `std::max` so it is fine); (3) whether `addHealth` internally honors god mode; (4) whether `handleEgg` leaving `frame >= ANIMZ_EGG_HATCH_LEN` on the newly typed actor (L817-L823) causes out-of-range sprite frames downstream.
- `spawnBullet` (L91-L116) hands out a raw `CActor*` into the `m_monsters` vector; `handleBossBullet` uses it safely today (L188-L197, no intervening push). Any future code between spawn and use that touches `m_monsters` invalidates it — consider returning an index instead if this API spreads.
- `m_spawns` entries with `active == 0` are never pruned (L54-L89); bounded by level lifetime, acceptable, but a `std::erase_if` at level load would keep the vector tidy.
- Interplay: `shadowActorMove` (game.cpp:1868) requires the actor to have a live grid entry to move at all; the deferred-delete design leaves dead entries in `m_monsterGrid` until end-of-tick rebuild, which is precisely why the missing `deletedMonsters` guards (High findings) reach "live" indices of already-dead actors.
