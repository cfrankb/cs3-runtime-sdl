# Audit: src/gamemixin.cpp + src/gamemixin.h
Date: 2026-11-17

## Summary
Overall the file is functional retro-game plumbing with mostly sound tile-blit math, but the render path has a cluster of unchecked `nullptr` frame dereferences (`CFrameSet::operator[]` returns `nullptr` + `LOGW` on out-of-range), one clear copy-paste bug (`drawUI` uses `getWidth()` for a Y offset), and several type-punning / integer-mask slips. Counts: Critical 1, High 2, Medium 8, Low 12.

## Findings

### Critical
- `gamemixin.cpp:811,815,900,971`: [bug] Unchecked null `CFrame *` dereference. `CFrameSet::operator[]` returns `nullptr` on out-of-range (src/shared/FrameSet.cpp:510–521); `calcSpecialFrame()` (cpp:2398–2426) can therefore return null, yet `drawViewPortDynamic` (`*tile` at 811/815), `drawViewPortStatic` (`*tile` at 900) and `drawBossses` (`*(*frames)[num]` at 971, `num = boss.currentFrame()` never range-checked) dereference unconditionally — data-driven crash (map/boss/sfx content with a bad animz/tile index). Fix: check `tile` before `drawTile` and skip (like cpp:756 already does for base tiles); validate `num < frames->size()` with `LOGW`. `calcSpecialFrame`'s idle branch `tiles[sprite.tileID]` (cpp:2403) and `getLayerTileDef(refID)` (cpp:869) have the same exposure (needs verification of sfx-id coverage).

### High
- `gamemixin.cpp:2616`: [bug] `const int baseY = getWidth() - ui.height() - ui.margin();` uses `getWidth()` where `whichButton()` correctly uses `getHeight()` (cpp:2630). On-view UI buttons are drawn at the wrong vertical position (off-screen for landscape resolutions) while click hit-testing uses the correct offset. Fix: `getHeight()`.
- `gamemixin.cpp:1363`: [ub] `*(reinterpret_cast<uint32_t *>(joyState))` type-puns a local `uint8_t[4]` as `uint32_t` — alignment is not guaranteed (UB; misaligned-load fault risk on Android/ARM targets) and it is endian-dependent. Fix: `joyState[0] | joyState[1] | joyState[2] | joyState[3]`.
- `gamemixin.cpp:2458–2471,2475–2487`: [bug] `drawHearth` writes via `CFrame::at()`, which **throws** `std::out_of_range` on invalid coords (src/shared/Frame.h:48–53). If `maxHealth()/2/FONT_SIZE` hearts ever exceed the bitmap width (small zoom window, large maxHealth), the render path throws an uncaught exception → terminate. Fix: clamp `maxHealth` to `(bitmap.width() - bx) / FONT_SIZE` or bounds-check before writing (needs verification of maxHealth range).

### Medium
- `gamemixin.cpp:1365` vs `gamemixin.cpp:1378`: [bug] Player walk-cycle advances with `(m_playerFrameOffset + 1) & PLAYER_STD_FRAMES` (mask 7 → values 0–7, since `PLAYER_STD_FRAMES = 7` is not a mask) in one branch and `% PLAYER_STD_FRAMES` (values 0–6) in the closure branch. Two different frame ranges for the same animation against an 8-frame stride (`PLAYER_FRAMES = 8`). Fix: pick one (likely `& (PLAYER_FRAMES - 1)`).
- `gamemixin.h:280,281,286` + `gamemixin.cpp:68–83`: [bug] `m_cx`, `m_cy`, `m_timer` have no in-class initializers and are not set by the ctor; `visualStates_t::sugarCubes` (gamemixin.h:234) is indeterminate until the first `clearVisualStates()`. Today initialization is guaranteed only by call ordering (`init`→`centerCamera`, intro→`m_timer = TICK_RATE` at cpp:1192). Fix: add NSDMIs (`int m_cx = 0;` etc., `uint8_t sugarCubes[SUGAR_CUBES] = {};`).
- `gamemixin.cpp:1016,1036`: [bug] `hpRatio = (float)boss.maxHp() / MAX_HP_GAUGE`; if a boss's data has `maxHp == 0`, `boss.hp() / hpRatio` divides by 0.0f and `static_cast<int>(inf)` is UB. Guard `maxHp > 0` (needs verification whether zero-maxHp boss data is possible).
- `gamemixin.h:163–173` + `gamemixin.cpp:1642–1680`: [dead] `PROMPT_RESTART_LEVEL` (gamemixin.h:170) is never set nor handled — `handlePrompts()` just clears it on Y with no action. Delete it. The whole `Prompt` enum plus `MAX_IDLE_CYCLES`, `IDLE_ACTIVATION`, `MIN_WIDTH_FULL`, `SUGAR_CUBES`, `SCREEN_SHAKES` and `visualStates_t` are duplicated verbatim in src/engine.h:190–213 — silent drift risk; keep one definition (`shrink:`).
- `gamemixin.cpp:2013,2027`: [error-handling] Return values of `write(m_recorderFile, name)` / `read(m_recorderFile, name)` are ignored; `playbackGame()` calls `openMusicForLevel()` and starts playback even when the save block failed to load. Check results, `LOGE` and abort on failure.
- `gamemixin.cpp:85–87` + `gamemixin.h:262,292`: [error-handling] `~CGameMixin()` never calls `stopRecorder()`. `CRecorder::stop()` writes the trailing batch size and closes the file (src/recorder.cpp:203–215); destroying mid-recording yields a truncated `test.rec`, and `m_recorderFile` (declared after `m_recorder`) is destroyed *before* it, leaving a dangling `IFile *` inside `CRecorder` during teardown (its dtor happens not to touch it). Call `stopRecorder()` in the destructor.
- `gamemixin.cpp:111–116,170–175`: [bug] Font lookup `(c - ' ') * fontOffset` yields a **negative** offset for control chars (`c < 0x20`), reading before `m_fontData` (help text / map strings come from data files); if `m_fontData` is empty (`preloadAssets()` not run) `data()` is null and the arithmetic itself is UB. Clamp: skip chars `< ' '` with `LOGW`.
- `gamemixin.h:294` + `gamemixin.cpp:2576–2579`: [shrink] manual `m_mutex.lock()/unlock()` around `loadLevel()`; an exception (e.g. `CFrame::at` throw) leaks the lock. Use `std::lock_guard`.

### Low
- `gamemixin.cpp:379–395`: [ub] `reinterpret_cast<uint64_t *>` blit violates strict aliasing and assumes even `width` (`d64 += width / 2`) and 8-byte-aligned dest; works in practice on LE/x86, but `memcpy` of the row would be identical cost optimized. Also note `#if __x86_64__ || __ppc64__` (cpp:61) mis-detects e.g. aarch64 Android as ENVIRONMENT32 — slow path only, but worth knowing.
- `gamemixin.cpp:1907–1914,1933–1941`: [bug] Save/rec format reads `size_t` via `sizeof(uint32_t)` / `sizeof(uint16_t)` chunks — little-endian-dependent, silently truncates on big-endian or names > 65535. Use `uint32_t`/`uint16_t` locals.
- `gamemixin.cpp:936–941`: [dead] `printRect` lambda + `(void)printRect;` — delete.
- `gamemixin.cpp:2032–2058` + `gamemixin.h:307`: [dead] `plotLine()` has no callers anywhere in `src/`; it also writes via the throwing `bitmap.at()` with no bounds check. Delete.
- `gamemixin.cpp:1558–1569`: [dead] `drawScores` scaleY chain: `if (h>=450) scaleY=3;` immediately followed by `if (h>=350) scaleY=3;` — first condition is a no-op (likely intended 4). Fix or collapse.
- `gamemixin.cpp:525–527`: [dead] inside `else if (m_currentEvent == EVENT_SUGAR)`, the test `m_currentEvent >= MSG0` is always false (that case was consumed by the earlier branch at 521), so `rectBG` is always `DARKGRAY`. Simplify.
- `gamemixin.cpp:2079`: [shrink] `const auto &line = std::move(message.lines[i]);` — `std::move` bound to a const ref is a no-op; remove it.
- `gamemixin.cpp:1790`: [shrink] `m_keyRepeters[k] ? --m_keyRepeters[k] : 0;` is an expression statement with a no-op arm; use `if (m_keyRepeters[k]) --m_keyRepeters[k];`.
- `gamemixin.h:80` + `gamemixin.cpp:1853–1858`: [bug] `getHiScoreAtIndex(i)` and `inputPlayerName()` (`m_hiscores[m_scoreRank]`) index without bounds/INVALID checks; a negative `m_scoreRank` would hit `m_hiscores[-1]`. Currently guarded only by the `m_recordScore` short-circuit at cpp:1139 — add an assert/clamp.
- `gamemixin.cpp:1066`: [error-handling] `LOGI("centerCamera ...")` fires on every re-center (each level start/restart); demote to debug or delete (log spam).
- `gamemixin.h:52,308–314` + `gamemixin.cpp:1513` etc.: [shrink] `isWithin`, `drawTimeout`, `drawKeys`, `drawSugarMeter`, both `drawTile`s and `tile2Frame` are declared `inline` in the header but defined only in gamemixin.cpp — an ODR trap if any other TU ever calls them; drop the `inline` keywords.
- `gamemixin.h:59–66`: [shrink] Without `USE_QFILE` the `protected slots:` label disappears and `mainLoop/save/load/setQuiet` silently become `public`; access level is coupled to a build flag — make access explicit in both branches.
- `gamemixin.cpp:466–481`: [bug] `drawKeys` decrements `x` by `TILE_SIZE` per held key with no lower clamp; at window widths < `MAX_KEYS * 16` (aggressive zoom), `drawTileFaz` writes left of the row start (needs verification vs minimum zoom width).
- `gamemixin.cpp:1120–1121,483–484`: [shrink] render functions mutate timing/input state (`drawLevelIntro` sets `m_timer`/`m_currentEvent`; `drawKeys` calls `decKeyIndicators()`); harmless in single-threaded tick but makes draw order significant — hoist into `mainLoop` if the loop is ever split.
- `gamemixin.cpp:1966–1991`: [shrink] `fazeScreen`/`flashScreen` use `bitmap.at()` per pixel (bounds-checked, throwing) over the whole framebuffer; iterate `getRGB()` directly.

## Notes
- The dynamic-camera half-tile math (cpp:723–780 + sprite overlay) was traced for edge OOB: with `ox`/`oy` offsets, `px`/`py` start at `-8` so the trailing half-column/half-row lands exactly at `cols*16` / `rows*16`; it does **not** overflow for the default 320×240 — but this relies on unasserted invariants (`drawTile` dest writes at cpp:267/337/430 are entirely unclipped). An ASan run with an odd-parity camera at a non-multiple-of-16 window size would confirm.
- `playerSpeed()` (src/game.cpp:1129) only returns nonzero constants, so the `m_ticks % game.playerSpeed()` mods at cpp:1328/1333/1349 are safe despite `cameraSpeed()` bothering to clamp — one clamp is enough (`shrink:`).
- Key/button population lives in runtime.cpp: `m_buttonState` is only indexed with values < `Button_Count` (11), and the `DPAD_UP..DPAD_RIGHT = 12..15` constants in gamemixin.h:195–198 are never used as `m_buttonState` indices — but they sit inside the same enum whose sentinel `Button_Count` sizes the array; a future `m_buttonState[DPAD_UP]` would be an OOB write. Consider moving DPAD values out of the counted range or sizing the array to 16. Also verify `m_keyStates[result]` (runtime.cpp:1352) can never index ≥ `Key_Count`.
- `m_hiscores[i].name` is `%s`-printed in `drawScores` (cpp:1595–1599); termination relies on `clearScores()`/`rankUserScore()` memsets plus the derived `loadScores()` — verify loadScores NUL-terminates names read from disk.
- Findings involving `CFrame::at()` throwing and `CFrameSet::operator[]` returning null are cross-file interplay (src/shared/Frame.h, src/shared/FrameSet.h); severity of the Critical cluster drops if all animz/sfx/boss indices are proven in-range by data validation elsewhere (`sanityTest()`).
