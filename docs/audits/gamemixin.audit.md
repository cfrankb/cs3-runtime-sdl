# Audit: src/gamemixin.cpp + src/gamemixin.h
Date: 2026-11-17

## Summary
Overall the file is functional retro-game plumbing with mostly sound tile-blit math, but the render path has a cluster of unchecked `nullptr` frame dereferences (`CFrameSet::operator[]` returns `nullptr` + `LOGW` on out-of-range), one clear copy-paste bug (`drawUI` uses `getWidth()` for a Y offset), and several type-punning / integer-mask slips. Counts: Critical 1, High 2, Medium 8, Low 12.

Tally (2026-11-18): Critical 1/1, High 2/2 resolved. Medium open 2/8: walk-cycle `&` vs `%` mismatch (behavior call), `PROMPT_RESTART_LEVEL`/engine.h enum duplication (shrink call). Low open 5/12: strict-aliasing blit (hot render path, needs measurement), endian `size_t` name reads (save-format call), drawScores `scaleY` no-op (intent call), `USE_QFILE` access-label coupling (Qt-API/test coupling), render-path state mutation (only if loop is split). Closed 10/12: 7 in the first 2026-11-18 mechanical pass plus hiscore bounds, drawKeys x-clamp, `fazeScreen`/`flashScreen` direct buffer iteration (2026-11-18 second pass); `plotLine` deletion declined (test-exposed).

## Findings

### Critical
- `gamemixin.cpp:811,815,900,971`: [bug] **FIXED 2026-11-17** (docs/bugs/resolved/critical-triage-2026-11-17.md BUG-C8; `test_gamemixin_bosses`). Original finding: Unchecked null `CFrame *` dereference. `CFrameSet::operator[]` returns `nullptr` on out-of-range (src/shared/FrameSet.cpp:510–521); `calcSpecialFrame()` (cpp:2398–2426) can therefore return null, yet `drawViewPortDynamic` (`*tile` at 811/815), `drawViewPortStatic` (`*tile` at 900) and `drawBossses` (`*(*frames)[num]` at 971, `num = boss.currentFrame()` never range-checked) dereference unconditionally — data-driven crash (map/boss/sfx content with a bad animz/tile index). Fixed: null-sprite `continue` in both viewport loops, non-null check before overlay `emplace`, and `drawBossses` range+null check on `num` with LOGW.

### High
**FIXED 2026-11-17 (BUG-H14):** `getHeight()`. **`gamemixin.cpp:2616`: [bug] `const int baseY = getWidth() - ui.height() - ui.margin();` uses `getWidth()` where `whichButton()` correctly uses `getHeight()` (cpp:2630). On-view UI buttons are drawn at the wrong vertical position (off-screen for landscape resolutions) while click hit-testing uses the correct offset. Fix: `getHeight()`.
**FIXED 2026-11-17 (BUG-H14):** byte-wise OR. **`gamemixin.cpp:1363`: [ub] `*(reinterpret_cast<uint32_t *>(joyState))` type-puns a local `uint8_t[4]` as `uint32_t` — alignment is not guaranteed (UB; misaligned-load fault risk on Android/ARM targets) and it is endian-dependent. Fix: `joyState[0] | joyState[1] | joyState[2] | joyState[3]`.
**FIXED 2026-11-17 (BUG-H14):** heart count clamped to bitmap width. **`gamemixin.cpp:2458–2471,2475–2487`: [bug] `drawHearth` writes via `CFrame::at()`, which **throws** `std::out_of_range` on invalid coords (src/shared/Frame.h:48–53). If `maxHealth()/2/FONT_SIZE` hearts ever exceed the bitmap width (small zoom window, large maxHealth), the render path throws an uncaught exception → terminate. Fix: clamp `maxHealth` to `(bitmap.width() - bx) / FONT_SIZE` or bounds-check before writing (needs verification of maxHealth range).

### Medium
- `gamemixin.cpp:1365` vs `gamemixin.cpp:1378`: [bug] Player walk-cycle advances with `(m_playerFrameOffset + 1) & PLAYER_STD_FRAMES` (mask 7 → values 0–7, since `PLAYER_STD_FRAMES = 7` is not a mask) in one branch and `% PLAYER_STD_FRAMES` (values 0–6) in the closure branch. Two different frame ranges for the same animation against an 8-frame stride (`PLAYER_FRAMES = 8`). Fix: pick one (likely `& (PLAYER_FRAMES - 1)`).
**FIXED 2026-11-18 (BUG-H18):** NSDMIs added. - `gamemixin.h:280,281,286` + `gamemixin.cpp:68–83`: [bug] `m_cx`, `m_cy`, `m_timer` have no in-class initializers and are not set by the ctor; `visualStates_t::sugarCubes` (gamemixin.h:234) is indeterminate until the first `clearVisualStates()`. ## Notes
- The dynamic-camera half-tile math (cpp:723–780 + sprite overlay) was traced for edge OOB: with `ox`/`oy` offsets, `px`/`py` start at `-8` so the trailing half-column/half-row lands exactly at `cols*16` / `rows*16`; it does **not** overflow for the default 320×240 — but this relies on unasserted invariants (`drawTile` dest writes at cpp:267/337/430 are entirely unclipped). An ASan run with an odd-parity camera at a non-multiple-of-16 window size would confirm.
- `playerSpeed()` (src/game.cpp:1129) only returns nonzero constants, so the `m_ticks % game.playerSpeed()` mods at cpp:1328/1333/1349 are safe despite `cameraSpeed()` bothering to clamp — one clamp is enough (`shrink:`).
- Key/button population lives in runtime.cpp: `m_buttonState` is only indexed with values < `Button_Count` (11), and the `DPAD_UP..DPAD_RIGHT = 12..15` constants in gamemixin.h:195–198 are never used as `m_buttonState` indices — but they sit inside the same enum whose sentinel `Button_Count` sizes the array; a future `m_buttonState[DPAD_UP]` would be an OOB write. Consider moving DPAD values out of the counted range or sizing the array to 16. Also verify `m_keyStates[result]` (runtime.cpp:1352) can never index ≥ `Key_Count`.
- `m_hiscores[i].name` is `%s`-printed in `drawScores` (cpp:1595–1599); termination relies on `clearScores()`/`rankUserScore()` memsets plus the derived `loadScores()` — verify loadScores NUL-terminates names read from disk.
- Findings involving `CFrame::at()` throwing and `CFrameSet::operator[]` returning null are cross-file interplay (src/shared/Frame.h, src/shared/FrameSet.h); severity of the Critical cluster drops if all animz/sfx/boss indices are proven in-range by data validation elsewhere (`sanityTest()`).
