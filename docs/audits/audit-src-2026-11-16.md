## Area 1 — Engine/runtime core
Files: runtime.cpp/h, main.cpp, parseargs.h, engine.cpp/h, engine_hw.cpp, events.h, logger.h, build.h, filemacros.h

### High
**FIXED 2026-11-17 (BUG-H1):** ****runtime.h:173 / runtime.cpp:877, 893** — `uint8_t m_mouseButtons[3]` indexed with SDL3 button IDs (LEFT=1 … X2=5). Right-click and X1/X2 clicks write indices 3–5 → out-of-bounds write into adjacent members (`m_input`, `m_hasFocus`). Triggered by ordinary mouse input.
**FIXED 2026-11-17 (BUG-H2):** ****runtime.cpp:1761-1762** — `takeScreenshot()`: `SDL_RenderReadPixels()` result dereferenced (`surface->format`) without NULL check → null deref on minimized window / GPU read failure.
**FIXED 2026-11-17 (BUG-H3):** ****engine_hw.cpp:1201-1203 (`drawTitlePix`)** — off-by-one: `if (i + 1 > size()) break;` permits `i+1 == size()`, then reads `m_assetFiles[ASSET_TITLESCREEN][i + 1]` → OOB vector read when a title row has fewer than `QUAD_COUNT + 1` fields.
**FIXED 2026-11-17 (BUG-H3):** ****engine_hw.cpp:1206-1214 (`drawTitlePix`)** — `src_low` built from `quad[0..3]` *before* the `quad.size() == QUAD_COUNT` guard at :1213 → OOB vector reads if the `atof` loop broke early.

### Medium
- **FIXED 2026-11-17 (commit `5ca9422`; verified 2026-11-18):** **runtime.cpp:1188, 2803** — `m_mouseButtons` is now `uint8_t m_mouseButtons[SDL_BUTTON_X2 + 1] = {}` (runtime.h:175), `memset` in `clearMouseButtons()` and again at runtime.cpp:580, and every write is gated by `button > 0 && button < sizeof(m_mouseButtons)` (:877). Original finding: `m_mouseButtons` never initialized (`clearMouseButtons()` had no callers); first reads were indeterminate.
- **FIXED 2026-11-17 (commit `5ca9422`; verified 2026-11-18):** **runtime.cpp:960** — the `SDL_EVENT_MOUSE_MOTION` handler now tests `event.motion.state & SDL_BUTTON_LMASK` (:965-966). Original finding: handler read `event.button.button` (inactive union member; motion carries `motion.state`) → UB read, meaningless button test.
- **FIXED 2026-11-17 (commit `5ca9422`; verified 2026-11-18):** **runtime.cpp:1098-1099** — the gamepad-button default case reads `event.gbutton.button` (:1068, :1104-1105). Original finding: default case logged/cast `event.button.button` instead of `event.gbutton.button` → inactive-union read, garbage output.
- **FIXED 2026-11-18 (BUG-H20; build+ctest):** **runtime.cpp (`initControllers`)** — now iterates the `SDL_GetJoysticks()` instance-ID array and `SDL_free`s it. Original finding: array never `SDL_free`d; `SDL_IsGamepad(i)`/`SDL_OpenGamepad(i)` passed array *index* but SDL3 takes joystick *instance IDs*.
- **FIXED 2026-11-18 (BUG-H20; build+ctest):** **runtime.cpp (`createResolutionList`, `listResolutions`)** — both `SDL_GetDisplays()` and `SDL_GetFullscreenDisplayModes()` arrays are now `SDL_free`d on every path, with NULL checks; `listResolutions` also bounds-checks `displayIndex`. Original finding: arrays never freed (no `SDL_free` call existed anywhere in `src/`).
- **FIXED 2026-11-18 (BUG-H20; build+ctest):** **runtime.cpp (`~CRuntime`)** — `SDL_Quit()` now called from the destructor, which runs on every `main()` return path (the `unique_ptr` in main.cpp). Original finding: `SDL_Quit` never called; `atexit(cleanup)` only logged.
- **runtime.cpp:1268 (`parseHelp`)** — `memcmp(line.data(), marker, 5)` without `line.size() >= 5` check → heap OOB read on short lines.
- **FIXED 2026-11-18 (BUG-H19; build+ctest):** **runtime.cpp (`loadScores`) + engine.cpp + gamemixin.cpp** — `file.read` return now checked (failure → `LOGE` + `clearScores()`); both hiscore prints use `%.16s`. Original finding: read return ignored; `hiscore_t::name[16]` loaded raw from file and printed with `%s` → overrun when no NUL byte present.
- **FIXED 2026-11-18 (BUG-H19; build+ctest):** **runtime.cpp (`openMusicForLevel`)** — empty `m_musicFiles` with no MUSIC meta now logs (`LOGW`) and returns. Original finding: `i % m_musicFiles.size()` → integer division by zero (SIGFPE).
- **runtime.cpp:2480-2487 vs 2314-2318, 1982, 2043** — resolution menu built from a *filtered* list (`rez.w < 640` skipped) but handlers index the *unfiltered* `m_resolutions` → silently wrong resolution whenever any entry is filtered.
- **FIXED 2026-11-18 (BUG-H19; build+ctest):** **runtime.cpp (`loadColorMaps`)** — bounds check on `userID` against `m_userNames.size()` (LOGW + return). Original finding: `m_userNames[userID]` with `userID` restored from savegame file, no bounds check → OOB read on crafted/foreign save.
- **FIXED 2026-11-17 (BUG-H10; verified 2026-11-18):** **runtime.cpp:3107-3112 (`isValidSavegame`)** — `CGame::validateSignature()` (game.cpp:1190-1204) now copies both signatures into NUL-terminated `char tmp[sizeof(GAME_SIGNATURE) + 1]` / `gameSig` buffers and logs only those, so the stack OOB read is gone; `memcmp` compares `sizeof(GAME_SIGNATURE)` bytes only. The `char sig[4]` at the runtime call site is unchanged and remains safe because nothing else consumes it as a C string. Original finding: `char sig[4]` read raw and passed to `CGame::validateSignature()`; `LOGW("%s", signature)` consumed a non-null-terminated stack buffer → stack OOB read.
- **FIXED 2026-11-18 (BUG-H19; build+ctest):** **runtime.cpp (`getScreenSize`)** — NULL `SDL_GetDesktopDisplayMode` result → `LOGW` + `Rez{0, 0}`. Original finding: may return NULL → deref `mode->w`.
- **FIXED 2026-11-18 (BUG-H19; build+ctest):** **runtime.cpp (`getSafeAreaWindow`)** — `SDL_Rect safe = {}` zero-init, so the documented Android divide-by-zero can no longer see garbage. Original finding: on `SDL_GetWindowSafeArea()` failure, returned uninitialized `SDL_Rect safe`.
